# 嘉立创 PCB 工作流

## 适用范围

按用户请求选择交接、布局、布线、铺铜或只读检查阶段。布局请求不自动升级成布线与铺铜；只读检查不自动修复。现有板的局部修改保留无关对象、锁定位置和已有走线。

本技能是指导，不是新增工具、权限或自动布局器。继续使用绑定当前 EDA 工程的原生 MCP 和原生权限；主要支持 `.eprj3`，不自动转换 `.eprj2` 或直接改写工程文件。

## 1. 读取真实状态

- 调用 `jlceda_context`，核对连接、工程、工作区和目标 PCB。保存 `target.documentTabId`，本次读取、修改与回读使用同一目标。
- 没有绑定工程或目标不正确时停止操作。不能选另一个 owner、启动另一个 MCP 或直接编辑文件绕过绑定。需要新工程时先由用户通过宿主建立并完成绑定。
- 需要从本工程原理图转入 PCB 时，先发现当前版本允许的原生交接/切换能力并确认范围。切换后作为新操作重新读取上下文；不拿原理图的文档 ID 操作 PCB。
- 用 `jlceda_help`、`jlceda_discover` 和原生文档确认方法、单位、层定义、坐标与角度约定。读实际板框、封装、焊盘、网络、走线、过孔、铜区、禁布区、锁定对象和已有规则中与本任务有关的状态。
- 板框为空、元件在板外、网络未导入都需要查明原因，不能单凭一个现象断言是初始布局或错误工程。

## 2. 明确本阶段约束

按需读取 [交接、布局与布线](references/design.md)。复用用户和工程已明确的板尺寸、层叠、固定接口位置、制造约束与电气要求；关键要求未知且影响设计时询问，不捏造线宽、间距、阻抗或过孔尺寸。

新 PCB：先核对原理图到 PCB 的网络、位号和封装关联，列出待完成阶段。已有 PCB：明确影响范围、必须保留的位置/规则和预期变化。只读检查：只收集证据与建议。

## 3. 执行当前阶段

- 使用现有 `jlceda_call` 的原生 `invoke` 与实际 `eda` API，保留 `documentTabId`。查询使用 `purpose: query`，写入使用 `purpose: modify`；这些标签不是权限机制。
- 写入前重新检查关键原值及锁定状态。所有 ID、网络和层来自真实读取，禁止编造；不要把连接关系从显示名称或飞线外观推断出来。
- 先满足板框、固定位置、禁布与器件位置等约束，再处理本次任务要求的连接。依赖前一步结果的修改顺序执行，适量分批并记录对象 ID 和 `jlcCall.id`。
- 移动已有布线的封装时，先确认原生操作对连接走线的实际行为与影响；不能假定自动保持连接。需要解锁、拆线或改板框而用户范围未覆盖时先说明影响并确认。
- 不为降低 DRC 数量而关闭规则、忽略网络或擅自修改制造约束。原生能力不足时说明具体限制，不改用另一套接口或直接改文件。

## 4. 回读与检查

读取 [检查与交付](references/verification.md)，另发 `purpose: verify` 的查询，可用 `verifyOf` 关联原修改，保留同一 `documentTabId`。

布局核对位置、旋转、板面、锁定对象和边界；布线核对实际网络、端点、层、宽度、过孔及连接；铺铜核对铜区网络、层、边界和实际更新状态。数据必须与本次预期比较，工具成功不是验证成功。

需要 DRC 时先确认原生能力，再实际运行并读取报告。未运行、报告不完整或接口不可用应明确说明；不能把飞线减少、图形看似相连或铜区轮廓存在当作完全连通、铺铜完成或 DRC 通过。

超时、断连、取消或 `DOCUMENT_CHANGED` 后停止原修改链。恢复并确认原目标后先回读，区分部分完成和未知结果，禁止自动重放写入或宣称已回滚。

## 5. 保存与交付

按请求和原生工作流单独保存（`purpose: save`），检查返回结果。说明目标 PCB、完成的阶段、实际回读证据、未连通/DRC 等已知问题和保存状态。

阶段完成不能声称整板可生产：初始布局不等于布线完成，DRC 通过也不等于 SI/PI、热设计、EMC 或制造审核已完成。只在用户要求且有真实能力和数据时继续这些工作。
