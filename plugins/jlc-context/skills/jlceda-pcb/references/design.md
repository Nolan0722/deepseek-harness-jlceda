# PCB 交接、布局与布线

## 原理图交接

- 读取实际原理图与 PCB 对应关系；必要时使用 `jlceda-schematic` 完成源设计核对，不在 PCB 中擅自改变电路定义。
- 通过原生文档发现导入/更新能力。更新前检查差异：新增、替换、删除封装与网络变化可能影响已有布局和布线。
- 对实体元件核实封装可解析、焊盘与引脚映射一致。不要用引脚数量相同或库名相似替代映射核对。
- 原生操作可能创建或切换图页。将这种转换视为阶段边界，重新读取宿主上下文后再编辑新文档；旧目标已变化时不要重试旧调用。

## 布局

- 明确板框、孔、禁布区、板面和锁定器件；不能根据板外元件分布猜板尺寸。
- 先处理已确定的连接器、机械位置与接口方向，再按电路功能安排元件。
- 去耦、振荡器、功率回路与敏感信号等位置要求依据真实电路和器件资料，不能仅用通用“靠近”代替具体连接判断。
- 检查旋转、镜像、底层放置及焊盘真实坐标，避免文本或封装外观被误当作可制造边界。
- 局部移动保留其他封装、规则、网络和锁定属性；锁定状态冲突时不静默解锁。
- 初始布局完成时报告布局检查结果及仍未完成的布线，不自动进入下一个阶段。

## 布线与过孔

- 读取真实网络、端点、可用层和已有规则，确定本次应连接的对象。
- 线宽、间距、过孔与层转换采用工程规则或已确认的设计要求。未知电流、层叠或阻抗要求不能用默认值冒充满足约束。
- 不因两段线重合就判定同网连通；核对端点、层与实际连接结果。
- 顺序处理依赖关系，局部修改后检查意外断开、残线及新增违反规则的对象。
- 不把通用自动布线等同于特定差分、等长或阻抗要求已满足；只有实际能力与报告支持时才能说明已完成。

## 铺铜

- 从真实网络确定铜区归属，核对所在层、边界、间距及相关规则。
- 创建或修改铜区轮廓与实际重新铺铜是两个需要核实的状态；以当前版本 API 的实际行为为准。
- 更新后按需要检查孤岛、间隙、连接及原生规则报告，不能只凭轮廓覆盖范围认定供电或地已连通。
