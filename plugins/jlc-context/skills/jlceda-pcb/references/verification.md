# PCB 检查与交付

## 按修改选择回读

- 封装放置：按对象 ID 查询位号、坐标、角度、层与锁定状态，对照预期位置和固定约束。
- 走线：查询实际网络、端点、宽度和层，检查本次涉及的焊盘是否通过原生连接数据连通。
- 过孔：查询网络、坐标、孔径、外径和层跨度；约束以工程与制造要求为准。
- 铜区：查询归属网络、层、轮廓及实际更新状态；能取得结果时再查连接、孤岛和规则问题。
- 删除/替换：核对目标是否真正移除、关联是否符合预期、是否遗留孤立对象；接口失败不能当成对象已不存在。
- 原理图更新：比较位号、封装、引脚/焊盘和网络变化，确认已有布局布线的影响。

查询必须是修改后的独立调用。写入时返回的对象或一次截图不能替代实际回读；能查到对象也不自动等于符合设计意图。

## DRC 与连接

先发现本版本的检查接口与报告结构，实际运行后记录范围、结果和剩余问题。若可以获取修改前报告，区分既有问题与本次引入的问题。

检查没有执行、尚未结束、报告被截断或只检查局部时，明确标注覆盖范围。不能将“未获取到错误”写成“零错误”。不能通过关闭规则或增加无依据豁免来消除问题。

飞线数量、网络数量和 DRC 数量各代表不同信息，应按任务解释。DRC 通过不证明功能正确、信号完整性、功率完整性、散热或制造可行性。

## 保存与阶段报告

保存独立执行并检查真实返回。未做关闭重开验证就不要声称已验证持久化恢复；不为验证而擅自关闭用户编辑器。

交付报告包含：目标 PCB、完成阶段、实际修改、回读证据、规则检查范围及结果、剩余连接/设计问题、保存状态。若只是完成初始布局，应明确布线与其他未请求的阶段尚未执行。

超时或连接恢复后先确认原工程和原图页，再查实际状态。结果未知时保留未知；既不宣称修改失败而盲目重做，也不宣称回滚成功。
