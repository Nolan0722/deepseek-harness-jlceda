# 原理图验证与交付

按任务选择检查，避免对改一个名称的任务执行无关的全工程审计。

## 修改后的证据

- 改属性：以稳定 ID 再查对象，核对新值和应保持的关联。
- 添加器件：核对实际返回的器件 ID、位号、型号、单元及放置状态，排除重复创建。
- 修改连接：读取相关引脚和网络归属，核对预期连接与不应产生的短接；必要时读取实际网表或连接信息。
- 删除对象：确认目标不存在，检查相关导线/网络是否产生非预期残留。删除后的 ID 查询报错需区分“不存在”与接口/连接失败。
- 整理排版：回读位置、旋转和相关端点；能取得预览时再核对遮挡与可读性。
- 更换器件/封装：核对电气功能、引脚编号与焊盘映射，不能仅比较引脚数。

原生返回成功、调用 ID 或执行完毕均不等于上述检查通过。回读的数据必须与具体预期比较。

## ERC 与保存

ERC 只有在当前版本存在可用接口、确实运行并读到报告后才能报告结果。区分既有问题与本次引入的问题；不通过关闭规则或无依据修改电路消除提示。

完成编辑后的保存单独调用并检查结果。保存成功不等于已经关闭重开验证，也不等于电气功能、仿真或制造验证通过。不为了验证而擅自关闭用户工程。

## 异常处理

调用超时或断连后，记录原目标和可能执行的修改。连接恢复且原目标确认一致后，先查实际状态。部分成功时只处理确认缺失的部分；状态无法确定时报告未知，不再重复写入。

用户切换图页或工程后，停止旧操作。不要用另一个图页的新 `documentTabId` 继续执行旧计划。需要转入本工程的其他图页时，明确新的任务范围并重新读取。

## 简短交付格式

- 目标：工程与图页。
- 修改：实际发生的变化；只读任务写“未修改”。
- 验证：比较了哪些真实值/连接，以及是否符合预期。
- 保存：已保存、仅内存修改、无需保存或未能确认。
- 待处理：实际报告的问题与未执行的检查，不虚构“全部通过”。
