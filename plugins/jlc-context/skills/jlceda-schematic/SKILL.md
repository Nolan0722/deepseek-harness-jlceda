# 嘉立创原理图工作流

## 适用范围

依据用户任务选择流程，不因打开原理图标签就开始绘制。新电路走完整流程；局部修改只处理相关器件、网络和图页。查询或审查请求保持只读，不自动修复、保存或创建工程。已有明确需求不重复确认。

本技能提供操作指导，不提供新工具，也不赋予额外权限。以宿主的工程绑定规则、原生权限和实时 MCP 返回为准。主要支持 `.eprj3`；不要因 `.eprj2` 自动转换格式或修改底层索引。

## 1. 读取真实状态与明确范围

- 调用 `jlceda_context`，检查连接、绑定工程、工作区和当前文档。保存 `target.documentTabId`，一个操作的读取、修改、回读必须使用同一个值。
- 没有绑定工程、连接异常、工程不一致时，停止 EDA 操作并说明具体原因。不要自行打开其他工程、切换 owner、启动另一套 MCP 或写工程文件绕过限制。需要新工程时，先让用户通过宿主新建并完成绑定。
- 用户要求的图页不是当前图页时，先确认正确目标。只在原生接口与宿主允许的范围内切换；切换后作为新操作重新读取上下文。遇到 `DOCUMENT_CHANGED` 停止旧操作，核对是否有部分修改，不能拿新 ID 盲目重试。
- 通过 `jlceda_help`、`jlceda_discover`、`jlceda_call` 的原生文档入口确认当前版本的查询与编辑方法。API 方法、对象 ID、坐标和返回结构均来自实际文档与读取结果，不从示例猜测。
- 读取相关器件、引脚、网络、导线、图页和已有封装关联。新建电路先整理用户已给出的供电、输入输出、功能和关键约束；只询问会改变方案且无法从工程或资料确定的问题。

## 2. 按任务规划

新电路或较大改动：先形成简短的功能分块、器件与连接计划，列出尚未确认的器件参数。必要的资料或计划保存在绑定工程目录，不能写到插件安装目录。不要要求简单改值任务生成整套设计文档。

局部修改：记录目标 ID、原值、预期结果及受影响的引脚/网络，保留无关内容。审查：列出证据与问题，不把建议变成隐含修改授权。

选型与绘制前按需读取 [器件、引脚与排版](references/design.md)。涉及交付、异常或检查结果时读取 [验证与交付](references/verification.md)。

## 3. 执行操作

- 继续使用现有 `jlceda_call`，通过原生 `invoke` 执行实际 `eda` API；不新增桥接服务器，不封装另一套工具，不直接改写工程文件。
- 查询标记 `purpose: query`，修改标记 `purpose: modify`。这是意图说明，不是权限隔离。
- 修改前再次核对关键原值；根据真实库器件、引脚编号与变换后的坐标放置和连接，不能按显示名称或图形接近程度认定已连接。
- 按功能块执行适量、可核对的修改，保留返回的对象 ID 和 `jlcCall.id`。有依赖关系的写入顺序执行；不宣称原生调用天然具有事务或自动回滚能力。
- 超时、断连或取消可能留下部分修改。先读取目标状态，确定差异后再决定下一步；禁止直接重复创建。

## 4. 独立回读验证

另发 `purpose: verify` 的查询，使用同一 `documentTabId`，可用 `verifyOf` 关联修改调用。对照计划核实真实器件属性、引脚连接、网络及相关封装。不能只复述写入返回值或把 `verified: false` 当成验证通过。

显示正确不等于电气连接正确；优先读取原生网络/连接信息。需要 ERC 时先发现本版本的实际能力，再运行并读取报告。接口不可用或未运行就明确说明，不推断“零错误”。

涉及 PCB 交接时，核实需要上板的器件具有可解析的封装及正确的引脚/焊盘对应关系；只有用户任务需要时才继续加载 `jlceda-pcb`，不自动布局或布线。

## 5. 保存与报告

完成用户要求的编辑后，按请求及原生工作流单独保存（`purpose: save`），检查保存返回结果。区分已修改、已回读、已保存；不支持确认持久化时说明限制。只读审查不触发保存。

回复简述目标图页、实际修改、独立回读证据、保存状态以及剩余问题。达到任务验收条件后停止，不为纯装饰反复重建整个电路。
